# Decisions: 자유 게시판

- Date: 2026-11-13
- Status: Confirmed
- Scope: 요구사항 인터뷰 완료. 구현과 상세 계획은 후속 단계에서 진행한다.

## D01. 이용 방식
- **Chosen**: 비회원 게시판. 닉네임과 비밀번호로 작성하고 해당 글의 비밀번호 확인 후 수정·삭제한다.
- **Rationale**: 사용자가 회원가입 없이 사용하는 방식을 선택했다.

## D02. 첫 버전 범위
- **Chosen**: 글 목록·상세·작성·수정·삭제, 검색, 페이지 나누기.
- **Rationale**: 기본 게시판을 먼저 완성한다. 댓글, 이미지 업로드, 회원가입, 조회수, 공지, 관리자 기능은 포함하지 않는다.

## D03. 실행 환경
- **Chosen**: 사용자 컴퓨터에서 로컬 실행. SQLite에 저장하여 서버를 재시작해도 글을 유지한다. 인터넷 배포는 후속 범위다.
- **Rationale**: 사용자가 로컬 실행을 선택했다.

## D04. 기술 구성
- **Chosen**: Next.js + SQLite. 화면과 서버를 하나의 프로젝트로 구성한다.
- **Rationale**: 사용자가 선택한 구성이다. 현재 저장소는 메모리 스타터킷이며 기존 웹앱이나 의존성 설정은 없다. Node.js, npm, Git 명령은 사용 가능하다. 구체적인 버전과 데이터 접근 라이브러리는 계획 단계에서 호환성을 확인한다.

## D05. 게시글 정보
- **Chosen**: 제목, 일반 텍스트 본문, 닉네임, 작성일 표시. 비밀번호는 화면과 조회 응답에 노출하지 않는다.
- **Rationale**: 사용자가 기본 정보와 일반 텍스트를 선택했다. HTML 편집기는 필요하지 않다.

## D06. 검색
- **Chosen**: 제목 또는 본문에 검색어가 포함된 글을 찾는다. 검색 결과에도 페이지 나누기를 적용한다.
- **Rationale**: 사용자가 제목과 본문 통합 검색을 선택했다.

## D07. 비밀번호
- **Chosen**: 8~64자. 원문 복원이 불가능한 비밀번호 전용 해시 방식으로 저장한다. 원문 저장과 조회를 금지하며 분실 시 복구는 지원하지 않는다.
- **Rationale**: 사용자가 8~64자와 복구 미지원을 선택했다. 최초 안내의 '암호화' 표현은 후속 안내에서 '해시'로 정정했다.

## D08. 화면
- **Chosen**: 밝은 배경의 깔끔한 기본형. PC는 표, 모바일은 세로 목록.
- **Rationale**: 사용자가 목록 중심 반응형 화면을 선택했다.

## D09. 정렬과 입력 제한
- **Chosen**: 최신 작성순, 페이지당 20개. 제목 1~100자, 본문 1~10,000자, 닉네임 2~20자.
- **Rationale**: 사용자가 기본 설정을 선택했다.

## D10. 기본 구현 원칙
- **Chosen**: 필수 텍스트의 공백만 입력은 거부한다. 입력 제한은 서버에서도 검증한다. 일반 텍스트를 안전하게 표시하고 데이터베이스 조회는 매개변수를 사용한다. 수정·삭제 비밀번호 오류, 없는 글, 빈 목록과 검색 결과 없음 상태를 안내한다. 삭제는 실행 전 재확인한다. 수정 시 최초 작성일은 유지한다.
- **Rationale**: 확정된 기능을 일관되고 안전하게 구현하기 위한 기본 처리다. 별도 사용자 선택이 아니라 구현 시 적용할 원칙이다.

## 기존 코드 확인 및 후속 유의사항
- 기존 웹앱과 인증·관리자 기능은 발견되지 않았다. 기존 기능을 재사용한다는 전제 없이 새 앱 초기화가 필요하다.
- `.memory/current.md`는 실제 작업이 아닌 템플릿 링크를 가리킨다. 계획 단계에서 실제 첫 작업으로 초기화한다.
- 기존 `.agents`, `.memory`, 예시 및 스타터킷 파일을 보존한다. 앱 배치 경로는 계획 단계에서 명시한다.
- 외부 공개와 그에 필요한 운영·스팸 대응 정책은 이번 범위에서 결정하지 않았다. 향후 공개 시 별도 설계가 필요하다.
